NO first/latest candidate fallback; NO latest-HEAD authority; NO package-provided publication commit authority; NO rename/copy-aware diff semantics; NO alternate diff-mode retry. Selector semantics were validated this session on throwaway synthetic /tmp Git worlds (evidence only, NON-AUTHORITY, world disposed): unique path introduction -> exactly 1 candidate; delete+re-add -> 2 candidates -> AMBIGUOUS fail-closed; identical-bytes rename presentation -> canonical no-renames `A`+`D` (rename-aware `-M` shows `R100`) with the selector still exactly 1; later path modification -> only the original introduction selected and the original blob remains readable from R.

## 13. Delete / modify / re-add semantics

A later modification or deletion of the fixed path MUST NOT replace the original R: R is the path-INTRODUCTION commit, its blob is immutable in history, and verification reads the publication bytes from R itself (HEAD-side content is NON-AUTHORITY). A later pure modification never creates a new qualifying candidate (R2 false for its parent) and never changes R. A delete followed by a re-add yields a SECOND qualifying path-introduction candidate, which makes the selector AMBIGUOUS and FAILS CLOSED (`CANONICAL_G10_RECEIPT_IDENTITY_PUBLICATION_AMBIGUOUS`); absent a separately authorized explicit supersession protocol the ORIGINAL publication remains the ONLY acceptable creation-time identity anchor. THIS TASK MUST NOT AND DOES NOT design, define or authorize any supersession protocol. Fail-closed unavailability is the accepted trade (the accepted PUBID-001 delete/re-add semantics, extended identically to this selector).

## 14. G11 independent re-derivation (design contract)

G11 MUST NOT trust: a package-provided R; latest HEAD; a cached G10 selector result; a cached receipt digest; a current-only receipt file; a rename-aware diff result. G11 INDEPENDENTLY: (1) re-parses the exact immutable grant bytes; (2) re-derives `grant_identity`; (3) re-derives the exact frozen package SHA-256 from the artifact bytes; (4) re-derives the canonical G7 publication identity (accepted G7 selector, canonical C4 semantics); (5) re-verifies the canonical receipt namespace identity (live object == pinned path/st_dev/st_ino, owner-uid, no group/world write, no symlink); (6) enumerates authoritative first-parent history; (7) re-derives canonical R by R1-R22; (8) re-reads the exact receipt-identity publication bytes from R; (9) extracts the ORIGINAL `receipt_path` / `receipt_sha256` / `receipt_size`; (10) opens/re-reads the CURRENT receipt bytes from the exact canonical namespace/path; (11) recomputes the current receipt SHA-256 and size; (12) requires: current receipt SHA-256 == ORIGINAL published `receipt_sha256` AND current receipt size == ORIGINAL published `receipt_size` AND current receipt canonical bytes == the exact receipt semantics derived from the exact grant/package/G7/namespace context (full canonicalization re-derivation, not only digest comparison) AND every cross-binding of Section 8 (grant/package/G7/namespace/role/slot/attempt/operator authority) exact. ANY mismatch: REFUSE (G11 acceptance FAIL CLOSED; no partial acceptance).

after publication but before G11 (G11); receipt deletion (receipt open fails -> REFUSE); receipt canonicalization substitution (full canonical-bytes re-derivation, `RIP_CANONICALIZATION_INVALID`/`RECEIPT_CANONICALIZATION_INVALID`); receipt path substitution (exact absolute `receipt_path` pin + re-derivation from grant_identity + namespace); receipt namespace substitution (namespace object pin st_dev/st_ino + owner/group/world gates); ## 16. Security argument (explicit proof)

BEFORE the design: an owner-writable receipt file could be replaced after O_EXCL creation, and later verification would observe only the CURRENT receipt — since the receipt semantics for one grant_identity are deterministic except `package_sha256`, the owner could rebind the current receipt bytes to a different frozen package digest, and nothing in the accepted corpus could prove which package was first-bound. AFTER the design: (1) the ORIGINAL canonical receipt bytes are constructed in memory from verified inputs (G10.1) — independent of the receipt file; (2) their SHA-256 and size are fixed BEFORE filesystem trust (G10.2) — independent of any later file state; (3) a canonical append-only Git publication records that ORIGINAL identity together with grant/package/G7/namespace cross-bindings (G10.5), is committed and pushed BEFORE G11, and its original path-introduction commit R is selected independently by authoritative first-parent history with exact-one no-renames raw-ADD semantics (Section 12) — the owner cannot silently replace R (modification never replaces R; delete/re-add makes the selector AMBIGUOUS and fails closed); (4) G11 independently re-derives R and compares the CURRENT receipt bytes against the PUBLISHED ORIGINAL identity (Section 14). Therefore mutating the receipt to bind PACKAGE_B after PACKAGE_A's original receipt cannot make PACKAGE_B the canonical first-bound package: the current-receipt-vs-original-publication comparison detects any byte/SHA/size/semantics divergence and REFUSES. `ONE_PACKAGE_ONLY` and `ONE_SHOT_IMMUTABLE_NON_RUNTIME_PACKAGE_BINDING` are thereby mechanically established for acceptance purposes. The argument does NOT depend on chmod/read-only state; permission hardening remains optional defense-in-depth.
