## 11. Security consequence

For one grant_identity the valid receipt semantic fields are deterministic except for the frozen package digest (the 10-field receipt schema pins schema/grant/event/role/slot/attempt/operator_authority/binding-semantics to grant-derived values; only `package_sha256` varies with the artifact). After an original receipt binds PACKAGE_A, an owner capable of writing the receipt file can replace the current canonical receipt bytes with another canonical receipt carrying PACKAGE_B's digest. Future verification re-derives PACKAGE_B's digest from PACKAGE_B bytes and checks against the CURRENT receipt. Without an independent original creation-time receipt identity, the verifier cannot prove that PACKAGE_A — rather than PACKAGE_B — was the first and only receipt-bound package. Thus `ONE_PACKAGE_ONLY` and `ONE_SHOT_IMMUTABLE_NON_RUNTIME_PACKAGE_BINDING` are not yet mechanically established. This is analogous in security shape to the previously remediated GRANT_ISSUED creation-time content-identity problem.
