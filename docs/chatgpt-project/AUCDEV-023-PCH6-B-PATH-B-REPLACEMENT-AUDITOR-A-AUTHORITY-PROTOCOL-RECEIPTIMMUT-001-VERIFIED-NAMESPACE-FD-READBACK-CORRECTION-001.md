## 4. The five distinguishable notions (independent examination)

The finding's substance reduces to conflating five distinct facts: (i) **equality of pathname strings** — a pure string fact about the published `receipt_path` derivation; (ii) **identity of the OPENED directory object** — what `fstat` on a held fd measures (binding.py opens the namespace once by its frozen absolute path, `O_RDONLY|O_DIRECTORY|O_NOFOLLOW`, lines 966-967, then verifies THE OPENED OBJECT by `fstat(fd)` against the pinned st_dev/st_ino plus the directory/owner/group/world gates, lines 971-982); (iii) **identity of the directory reached by a LATER absolute-pathname resolution** — a lookup-time fact determined by the live dentry tree at that later instant, NOT bound by (ii): the pin constrains the object it verified, not the target of a subsequent lookup keyed by the same string; (iv) **identity of the receipt FILE object** — explicitly NOT a pinned identity under the accepted DESIGN-001 disposition (RI-T05; zero receipt-file stat anywhere in binding.py — machine-verified), UNCHANGED by this correction; (v) **equality of the original and current receipt BYTES** — the content identity the G10.4/G10.6/G11 comparisons enforce. Section 10(c)'s error is precisely the inference (iii) == (ii) from the pin plus name determinism: it treats a VERIFIED OBJECT as if it were a BOUND LOOKUP TARGET. The accepted source's own pattern is the correct one: the pathname participates exactly ONCE, as the locator of a single atomic namespace open whose identity is verified on the resulting object; every subsequent access — including the receipt open — goes through the held fd (`os.open(name, ..., dir_fd=dir_fd)`, lines 1065-1066 create / 1102 read), so no later pathname lookup can intervene.

- **R-NS-7.** NO previously checked pathname may be claimed to guarantee the object reached by a later pathname lookup. A pathname is a lookup key, not an immutable filesystem object handle; only a held fd — identity-verified by `fstat` on the opened object — pins the object for subsequent access. The pathname participates exactly ONCE per readback step, as the locator of the single atomic namespace open.
- **R-NS-8.** On ANY of: directory identity mismatch; failed receipt open; ambiguous resolution; receipt canonicalization failure; original-vs-current mismatch — REFUSE / FAIL CLOSED (G10 FAIL CLOSED / `G11_REFUSED` with the specific accepted mismatch constant). - **R-NS-9.** G10.6 post-push original-vs-current receipt comparison and G11 independent re-derivation are PRESERVED exactly (design Sections 11/14), now mechanically anchored to the verified held fd.
- **R-NS-10.** Nothing in this rule introduces receipt inode pinning, a new publication field, a new grant/receipt schema field, a new governance stage, an alternate namespace, a second receipt reader authority, a new runtime API or a supersession mechanism.
