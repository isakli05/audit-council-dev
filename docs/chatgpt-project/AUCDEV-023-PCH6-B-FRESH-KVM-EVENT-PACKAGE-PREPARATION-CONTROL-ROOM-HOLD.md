ID: `AUCDEV023-CR-PCH6B-EVP-RB-002`
Title: BOUNDARY_LAUNCHER_BOOTSTRAP_FD_ARGV_ABI_MISMATCH
Classification: HARNESS / EVENT-PACKAGE PROTOCOL DEFECT
Support: OBSERVED SOURCE FACT + MECHANICALLY IMPLIED EXECUTION FAILURE
Disposition: OPEN / BLOCKING

The current bootstrap-authority child ABI is mechanically fixed
(`runtime.py::CRED_FD/FAIL_FD/AUDITOR_EXEC_FD/AUDITOR_INVOCATION_FD`
and `_child_setup`): immediately before the boundary exec the authority

invocation, and execs the verified boundary launcher with argv
containing `--role <AUDITOR_A|AUDITOR_B>`, `--attempt <reserved
attempt>`, `--event <event-id>` (launcher argv identity, `--role`,
`--attempt`, `--event` per `_fork_and_launch`).

The frozen package boundary `boundary/frevp_launcher.py` instead
defines an argparse interface requiring `--role client|tool`
(choices), `--evidence`, `--target`, `--out-src`, `--bnd` (all
required), optional `--cred-init` (a credential-init DIRECTORY
argument), plus an explicit client_argv REMAINDER tail. It does not
implement the bootstrap-authority fixed FD 3/5/6 protocol: it does not
read the sealed canonical invocation from FD 6, does not exec the held
verified auditor executable through FD 5, and expects credential
material through a `--cred-init` directory rather than materializing
the authority-supplied sealed credential FD 3. Its exec path is
